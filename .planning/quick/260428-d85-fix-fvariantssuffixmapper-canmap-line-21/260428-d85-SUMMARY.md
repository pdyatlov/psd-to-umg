# Quick Fix 260428-d85: Fix FVariantsSuffixMapper::CanMap line 21 Summary

**One-liner:** Fixed CanMap predicate to accept EPsdTagType::Canvas (the D-02 implicit Group default) so bare `@variants` groups route to FVariantsSuffixMapper instead of being rejected.

## What Was Done

FVariantsSuffixMapper::CanMap used `!Layer.ParsedTags.HasType()` as a guard to prevent explicit-type layers (e.g. `@button @variants`) from being claimed by the variants mapper. However, FLayerTagParser's D-02 default-type pass assigns `EPsdTagType::Canvas` to every `EPsdLayerType::Group` layer — meaning bare `@variants` groups had `HasType() == true`, causing CanMap to return false for them. This was the opposite of intended behaviour.

**Fix:** Replaced `!HasType()` with an explicit two-value check:

```cpp
return Layer.ParsedTags.bIsVariants
    && (Layer.ParsedTags.Type == EPsdTagType::None
        || Layer.ParsedTags.Type == EPsdTagType::Canvas);
```

**Invariant verification:**
- `MyGroup @variants` with `EPsdLayerType::Group` → `Type=Canvas` → `Canvas` matches second condition → `CanMap` returns `true`. Correct.
- `MyBtn @button @variants` → `Type=Button` → neither `None` nor `Canvas` → `CanMap` returns `false` (FButtonLayerMapper wins). Correct.
